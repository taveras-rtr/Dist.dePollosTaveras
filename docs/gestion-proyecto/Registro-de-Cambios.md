# Registro de cambios del proyecto

**Proyecto:** Dist. de Pollos Taveras  
**Asignatura:** Ingeniería de Software I

Este registro resume cinco avances realizados durante el análisis, diseño y organización del proyecto, indicando los cambios efectuados y su contribución al desarrollo.

| N.º | Cambio o avance | Descripción | Resultado |
|---|---|---|---|
| 1 | Elaboración del README | Se organizó la descripción general del sistema, sus objetivos, alcance, funcionalidades propuestas y estructura técnica. | Se estableció un documento principal para presentar el proyecto. |
| 2 | Especificación de requisitos | Se documentaron los requisitos funcionales y no funcionales, los criterios de aceptación y las relaciones entre los requisitos. | Se estableció una referencia para orientar el análisis y el diseño. |
| 3 | Incorporación de diagramas UML | Se incorporaron los diagramas de casos de uso, clases, secuencia, actividades y componentes. | Se representaron visualmente distintos aspectos de la estructura y el comportamiento propuesto. |
| 4 | Documentación de la arquitectura | Se describió una propuesta de arquitectura lógica por capas, con responsabilidades diferenciadas para presentación, lógica de negocio y acceso a datos. | Se estableció una referencia arquitectónica para organizar el sistema. |
| 5 | Organización de tareas y riesgos | Se documentaron cinco historias de usuario y cuatro riesgos técnicos mediante GitHub Issues, y se organizó el seguimiento del trabajo en GitHub Projects. | Se estableció una estructura para priorizar tareas, controlar estados y documentar riesgos. |

## Observaciones

Los cambios registrados corresponden a avances documentales, de modelado y de gestión del proyecto académico. La documentación de una funcionalidad o de una propuesta de diseño no implica que esta se encuentre implementada o validada mediante pruebas.

El seguimiento de las modificaciones se realiza mediante Git y GitHub, mientras que las tareas y los riesgos se organizan mediante Issues y Projects.
