# Nota técnica de versión

## Proyecto: Dist. de Pollos Taveras

**Versión:** 1.0.0  
**Tipo de versión:** Línea base documental y de diseño  
**Fecha:** 9 de octubre de 2026  
**Estado:** En desarrollo académico

## 1. Descripción de la versión

La versión 1.0.0 establece una base documental para el análisis, diseño y planificación del sistema Dist. de Pollos Taveras.

Esta versión reúne los principales documentos técnicos y modelos elaborados durante el proyecto académico de Ingeniería de Software I. Su propósito es mantener organizada la información y establecer una referencia para las siguientes actividades de desarrollo.

## 2. Contenido de la versión

La versión incluye los siguientes elementos:

- README.md con la descripción general, los objetivos y el alcance del sistema.
- Especificación de requisitos funcionales y no funcionales.
- Propuesta de arquitectura lógica por capas.
- Diagrama UML de casos de uso.
- Diagrama UML de clases.
- Diagrama UML de secuencia.
- Diagrama UML de actividades.
- Diagrama UML de componentes.
- Historias de usuario documentadas mediante GitHub Issues.
- Riesgos técnicos identificados y registrados en GitHub Issues.
- Tablero de GitHub Projects para organizar las tareas, prioridades y estados.
- Registro de avances del proyecto.

## 3. Cambios registrados

Los principales avances documentales de esta versión son:

1. Organización de la documentación general del proyecto.
2. Definición de los requisitos del sistema.
3. Incorporación de los diagramas UML.
4. Documentación de la arquitectura propuesta.
5. Organización de las historias de usuario y los riesgos técnicos.
6. Registro de avances y planificación mediante GitHub Projects.

Los cambios se registran mediante el control de versiones de Git y GitHub para facilitar el seguimiento de las modificaciones realizadas.

## 4. Aspectos pendientes

Para continuar la evolución del proyecto, quedan pendientes las siguientes actividades:

- Revisar la coherencia entre los requisitos, la arquitectura y los diagramas UML.
- Verificar la trazabilidad entre los requisitos y las historias de usuario.
- Completar el seguimiento de las tareas y los riesgos en GitHub Projects.
- Definir y documentar los casos de prueba.
- Validar las funcionalidades cuando estén implementadas.
- Registrar los resultados de las pruebas y las correcciones realizadas.
- Actualizar la documentación cuando se produzcan cambios relevantes.

## 5. Riesgos técnicos

Durante la planificación se identificaron los siguientes riesgos potenciales:

- R01: Errores en la base de datos.
- R02: Errores durante la integración de los módulos.
- R03: Cambios o ampliación de los requisitos.
- R04: Retrasos en el desarrollo de las funcionalidades.

Estos riesgos cuentan con acciones de seguimiento documentadas en GitHub Issues. Su identificación no significa que todos se hayan materializado ni que estén resueltos.

## 6. Próximo paso técnico

El siguiente paso consiste en revisar la consistencia entre los requisitos funcionales, la arquitectura lógica por capas y los diagramas UML.

Posteriormente, se podrán definir los casos de prueba y planificar la implementación y validación progresiva de las funcionalidades, manteniendo actualizados los documentos y el tablero del proyecto.

## 7. Consideraciones de la versión

Esta versión representa una línea base documental y de diseño del proyecto académico.

La inclusión de requisitos, diagramas y propuestas arquitectónicas no implica que todas las funcionalidades estén implementadas, integradas o verificadas mediante pruebas.

La versión podrá actualizarse conforme se completen nuevas actividades y se disponga de evidencias de implementación y validación.

## 8. Control de cambios

Las modificaciones de los documentos se gestionan mediante Git y GitHub. Los commits permiten identificar los cambios registrados y consultar su historial.

Las tareas, historias de usuario y riesgos se organizan mediante GitHub Issues y GitHub Projects para facilitar el seguimiento del trabajo.
