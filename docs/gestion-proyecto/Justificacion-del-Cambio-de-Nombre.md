# Justificación del cambio de nombre del sistema

## 1. Contexto

Durante la organización y documentación del proyecto desarrollado en la asignatura Ingeniería de Software I, se decidió modificar el nombre del sistema, pasando de "Dist. de Pollos Taveras" a "SDP (Sistema de Distribución de Pollos)".

Esta decisión responde a la intención de presentar el software como un producto independiente, sin vincularlo exclusivamente con una empresa específica. Aunque el proyecto utiliza una empresa ficticia como contexto para identificar las necesidades comerciales, la solución propuesta está orientada al sector de la distribución de pollos.

## 2. Motivos del cambio

La modificación del nombre se fundamenta en los siguientes aspectos:

- **Identidad del producto:** permite identificar el sistema como una solución informática independiente de una empresa particular.
- **Brevedad y facilidad de reconocimiento:** las siglas SDP ofrecen una denominación corta y fácil de utilizar en la documentación técnica.
- **Presentación comercial:** el nuevo nombre proporciona una identidad más general y apropiada para presentar el sistema como un producto de software.
- **Coherencia documental:** facilita mantener una denominación uniforme en el README, los diagramas UML, la documentación técnica y las evidencias del proyecto.
- **Proyección futura:** permite plantear el sistema como una solución que podría adaptarse a las necesidades de diferentes empresas dedicadas a la distribución de pollos.

## 3. Descripción del nuevo nombre

**Nombre anterior:** Dist. de Pollos Taveras.

**Nombre actual:** SDP.

**Significado:** Sistema de Distribución de Pollos.

El nuevo nombre describe la finalidad general del software y permite identificarlo de manera sencilla en los documentos, las herramientas de seguimiento y las presentaciones académicas.

## 4. Alcance de la modificación

El cambio corresponde a la identidad y denominación del sistema. No implica modificaciones en su propósito, los requisitos definidos, las funcionalidades contempladas, los modelos UML ni la arquitectura propuesta.

Se conservarán los elementos técnicos desarrollados durante el proyecto, actualizando las referencias al nombre anterior cuando corresponda para mantener la coherencia documental.

El repositorio de GitHub conservará su dirección actual, salvo que posteriormente se decida modificarla. El nombre del repositorio no tiene que coincidir necesariamente con el nombre comercial del sistema.

## 5. Acciones de actualización

Para mantener la consistencia del proyecto, se consideran las siguientes acciones:

- Actualizar el título y las referencias del README.md.
- Revisar los documentos técnicos para sustituir el nombre anterior cuando identifique al sistema.
- Actualizar los títulos de los diagramas UML cuando corresponda.
- Mantener la coherencia del nombre en GitHub Issues y GitHub Projects.
- Revisar las evidencias que se incorporarán al informe final.
- Registrar el cambio en el historial de modificaciones del proyecto.

## 6. Conclusión

La adopción de SDP (Sistema de Distribución de Pollos) busca proporcionar una identidad más clara, breve e independiente al producto de software. Esta decisión mejora la presentación del proyecto y facilita la uniformidad de su documentación, manteniendo el enfoque, los objetivos y el trabajo técnico desarrollado durante la asignatura Ingeniería de Software I.
