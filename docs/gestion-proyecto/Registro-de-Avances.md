# Registro de avances del proyecto

## Proyecto: Dist. de Pollos Taveras

**Asignatura:** Ingeniería de Software I  
**Tipo de proyecto:** Académico

## Introducción

Este documento registra los principales avances realizados durante el análisis, diseño y organización del proyecto Dist. de Pollos Taveras. Su propósito es mantener evidencia de los entregables elaborados y facilitar el seguimiento del trabajo mediante la documentación técnica y las herramientas de colaboración de GitHub.

## 1. Documentación general del sistema

**Avance:** Elaboración del README principal.

**Descripción:** Se documentó la descripción general del sistema, el problema que se busca abordar, los objetivos, el alcance funcional, las tecnologías consideradas y la organización propuesta entre frontend y backend.

**Evidencia:** `README.md`.

**Resultado:** Se estableció un punto de entrada para comprender el propósito y la organización del proyecto.

## 2. Especificación de requisitos

**Avance:** Elaboración de los requisitos funcionales y no funcionales.

**Descripción:** Se organizaron los requisitos del sistema, incluyendo las funcionalidades previstas, las restricciones técnicas, los criterios de aceptación y las relaciones entre los requisitos.

**Evidencia:** `docs/requisitos/Requisitos-del-Sistema.md`.

**Resultado:** Se estableció una referencia para orientar el diseño y la planificación de las funcionalidades.

## 3. Modelado mediante diagramas UML

**Avance:** Incorporación de los diagramas UML del sistema.

**Descripción:** Se incorporaron los diagramas de casos de uso, clases, secuencia, actividades y componentes para representar distintos aspectos del comportamiento y la estructura propuesta del sistema.

**Evidencia:** `docs/uml/`.

**Resultado:** Se obtuvo una representación visual de los actores, las clases, las interacciones, los procesos y la organización modular propuesta.

## 4. Documentación de la arquitectura

**Avance:** Definición de la propuesta de arquitectura lógica por capas.

**Descripción:** Se documentaron las responsabilidades de las capas de presentación, lógica de negocio y acceso a datos, junto con su relación con la base de datos.

**Evidencia:** `docs/arquitectura/Arquitectura-del-Sistema.md`.

**Resultado:** Se estableció una referencia arquitectónica para organizar las responsabilidades y facilitar el mantenimiento del sistema.

## 5. Gestión del proyecto y seguimiento de riesgos

**Avance:** Organización de historias de usuario, riesgos técnicos y tareas en GitHub.

**Descripción:** Se utilizaron GitHub Issues para documentar las historias de usuario y los riesgos identificados. También se organizó el trabajo mediante GitHub Projects, utilizando estados, prioridades y fechas estimadas para facilitar el seguimiento.

Los riesgos documentados incluyen posibles errores en la base de datos, problemas de integración entre módulos, cambios en los requisitos y retrasos en el desarrollo.

**Evidencia:** Issues y tablero de GitHub Projects.

**Resultado:** Se estableció una estructura de seguimiento que permite organizar las tareas, documentar los riesgos y mantener visible el estado del trabajo.

## Conclusión

Los avances registrados proporcionan una base documental para el análisis y diseño del sistema Dist. de Pollos Taveras. La combinación de requisitos, arquitectura, diagramas UML y herramientas de gestión permite mantener una relación entre las necesidades identificadas y las actividades planificadas.

Este registro describe los entregables documentales y de planificación del proyecto. No implica que todas las funcionalidades estén implementadas, integradas o verificadas mediante pruebas.
